# 인쇄물 템플릿 — 자료 구조와 만드는 법

`/print` 아래 마흔여덟 장(갈래마다 여덟 장)이 어떻게 생겼고, 어떻게 한 장을
더하는지 적어 둔 문서입니다. 편집기 자체의 구조는 `print-editor-decisions.md`,
글꼴 사정은 `print-fonts.md` 에 따로 있습니다.

## 한눈에

```
lib/print/
  specs.ts          갈래·규격·재단 여백·안전선·dpi      ← «무엇을 만들 수 있는가»
  taxonomy.ts       업종·스타일·색 딱지                  ← «어떻게 찾아지는가»
  art.json          생성 그림 목록과 프롬프트            ← 사람이 적고 스크립트가 채웁니다
  art.ts            art.json 을 읽는 얇은 층
  templates/
    kit.ts          색·연필·조판 도우미
    flyer.ts        전단지 여덟 장
    coupon.ts       쿠폰 여덟 장
    poster.ts       포스터 여덟 장
    banner.ts       현수막 여덟 장
    standing-banner.ts  배너 여덟 장
    menu.ts         메뉴판 여덟 장
    index.ts        모아서 거르기·찾기까지
scripts/
  print-art.mjs     art.json 을 보고 그림을 만듭니다
  print-og.mjs      갈래마다 카카오톡 미리보기 그림
  print-check.mjs   마흔여덟 장을 기계가 훑습니다
app/print/check/    마흔여덟 장을 브라우저에서 실제로 돌려 봅니다
```

## 템플릿 한 장의 모양

```ts
{
  id: "flyer-cafe-open",        // 주소에 그대로 들어갑니다. 바꾸면 링크가 죽습니다
  name: "로스터리 오픈",
  note: "사진 한 장을 위에 크게. 뒷면은 차림표로 받습니다.",
  industry: "cafe",             // taxonomy.ts 의 id
  style: "photo",
  palette: ["warm", "ink"],
  art: ["flyer-cafe-photo"],    // art.json 의 id
  tags: ["오픈", "카페", "양면"],
  doc: { …PrintDoc }            // 편집기가 그대로 여는 문서
}
```

`doc` 은 편집기가 저장하는 것과 **똑같은** 자료형입니다(`lib/print/types.ts`).
그래서 템플릿을 열면 곧바로 편집이 되고, 편집한 것을 다시 템플릿으로 만들
수도 있습니다.

필드를 더할 때는 반드시 **선택(optional)** 으로 더하세요. 이미 저장된 문서가
새 필드를 모른 채로도 열려야 합니다.

## 한 장 더하기

갈래 파일에 초안(`Draft`) 하나를 넣으면 끝입니다. `index.ts` 는 손대지
않아도 됩니다.

```ts
{
  id: "flyer-yoga-open",
  name: "요가원 개원",
  note: "빈 벽 사진과 큰 글자 하나.",
  industry: "fitness",
  style: "photo",
  palette: ["mono", "ink"],
  size: "a4",                    // 비우면 그 갈래의 기본 규격
  background: { color: "#ffffff" },
  build: ({ w, bleed }) => [
    image("flyer-fitness-photo", { x: -bleed, y: -bleed, w: w + bleed * 2, h: 160 }),
    text({ x: 16, y: 180, w: w - 32, h: 30, text: "3월 2일 문을 엽니다", size: 26, weight: 700 }),
    …
  ],
}
```

`build` 는 종이 크기(`w`, `h`, `safe`, `bleed`)를 받아 요소 배열을 돌려줍니다.
좌표는 전부 **mm**, 글자 크기만 **pt** 입니다. `image()` 는 그림이 아직 없으면
`null` 을 돌려주고 `compose` 가 걸러 냅니다 — 키 없이 저장소만 받은 사람도
사이트를 띄울 수 있어야 하기 때문입니다.

### 지켜야 하는 것

`npm run print:check` 가 세는 것들입니다. 오류가 하나라도 있으면 나가는 값이
0 이 아닙니다.

| 항목 | 기준 | 왜 |
| --- | --- | --- |
| 안전선 | 글자는 `safe` 안쪽에 | 재단에서 잘려 나갑니다 |
| 종이 밖 | 어떤 요소도 종이를 완전히 벗어나면 안 됨 | 열었을 때 안 보입니다 |
| 작은 글씨 | 쿠폰 6.8pt · 메뉴 7.5pt · 전단 8pt · 포스터 9pt | 그 아래는 인쇄하면 뭉갭니다 |
| 글꼴 | 한 장에 두 벌까지 | 셋을 넘으면 «만들다 만 것» 으로 보입니다 |
| 색 갈래 | 세 갈래까지(색상환 30도 묶음, 무채색은 한 갈래) | 절제된 팔레트 |
| 사진 해상도 | 인쇄 해상도의 절반 이상(최소 72dpi) | 현수막과 전단지의 기준이 다릅니다 |
| 글자 요소 | 세 개 이상 | 통째로 구운 그림은 편집기가 아니라 액자입니다 |

색 기준을 «색상값 개수» 가 아니라 «색상환 묶음» 으로 세는 이유는, 같은 남색의
밝기 차이 넷을 «색 네 가지» 로 세면 절제된 팔레트를 벌주는 셈이 되기 때문입니다.

### 접히는 인쇄물

메뉴판 2단은 210mm, 3단은 99mm 마다 접힙니다. 그 선 좌우 6mm 안에는 글자를
두지 않았습니다. 접힌 자리에 걸친 글자는 인쇄는 되지만 읽히지 않습니다.

### 양면

`doc.duplex` 가 참인 갈래(전단지·쿠폰·메뉴판)에서만 씁니다. 뒷면 요소는
`side: "back"` 을 답니다. `priceRow`·`bullets` 같은 도우미도 `side` 를 받으니
잊지 마세요 — 이걸 빠뜨리면 뒷면 목록이 앞면에 겹쳐 그려집니다.

## 그림

`lib/print/art.json` 이 원본입니다. 사람이 `prompt` 를 적고, 스크립트가
`file`·`width`·`height`·`model` 을 채웁니다.

```bash
export GEMINI_API_KEY=발급받은키
npm run print:art                      아직 없는 것만
npm run print:art -- --all             있어도 다시
npm run print:art -- poster            그 갈래만
npm run print:art -- --id menu-linen-texture
npm run print:art -- --sheet           만든 것을 한 장에 붙여 훑어보기
```

프롬프트에는 `suffix` 가 자동으로 붙습니다 — «글자를 그려 넣지 마라, 여백을
남겨라, 테두리 없이 가득 채워라». 특히 마지막이 중요합니다. 그냥 두면 모델이
«액자에 든 그림» 을 그려 주고, 그러면 전면 배경으로 쓸 수 없습니다. 실제로
첫 판에서 다섯 장이 그렇게 나와 다시 뽑았습니다.

만든 뒤에는 `--sheet` 로 한 번 훑어보세요. 손가락이 여섯 개인 사람, 깨진
글자, 왜곡된 건물은 기계가 못 잡습니다.

### 작은 판을 반드시 함께 만드세요

```bash
npm run print:variants          없는 것만
npm run print:variants -- --all 전부 다시
```

원본은 3584 × 4800 이고 목록의 썸네일은 130px 입니다. 원본을 그대로 쓰면
갈래 목록 한 장이 9.5MB, 허브가 18.7MB 를 내려받습니다. 실제로 그렇게
올라갔고 «인쇄물 쪽에 들어가면 너무 오래 걸린다» 는 말을 들었습니다.

그래서 같은 그림을 세 벌로 둡니다 — 원본(내보내기 전용), md 1400px,
sm 520px. 화면에 그리는 쪽은 `variantUrl` 로 알아서 갈아 끼우고(DocThumb
가 상자 크기를 보고 고릅니다), 문서에 저장되는 주소는 언제나 원본입니다.
PDF 로 내보낼 때 그 해상도가 필요하기 때문입니다.

지금은 허브 103KB · 갈래 목록 45~56KB 입니다. 그림을 더하면 **반드시**
이 스크립트를 다시 돌리세요. 빠뜨려도 화면은 원본으로 되돌아가 그대로
보이지만, 그만큼 느려집니다.

### 프롬프트는 스톡 사진 캡션이 아니어야 합니다

첫 판에서 «Overhead photograph of a wooden cafe counter in warm morning
light, a ceramic dripper, scattered coffee beans» 같은 문장을 썼습니다.
그건 스톡 사진의 캡션이고, 그래서 스톡 사진이 나왔습니다.

사진가가 실제로 정하는 것을 적으면 결과가 달라집니다 — 렌즈와 거리, 빛의
방향과 세기, 필름이나 그레이딩, 일부러 프레임 밖으로 뺀 것, 남겨 둔 흠.
같은 카페 배경을 «35mm Portra 400, 왼쪽 창에서 들어온 센 오후 햇빛이 긁힌
참나무 상판을 가로질러 드리퍼의 긴 그림자를 만든다, 원두 몇 알은 프레임
밖으로 굴러 나갔고, 커피가 밴 리넨 천이 오른쪽 끝으로 밀려 있다» 로 바꾸자
쓸 만한 사진이 나왔습니다.

훑어보기(`--sheet`)로는 이 차이가 보이지 않습니다. 420px 로 줄이면 뭐든
괜찮아 보입니다. **원본 크기로 한 장씩** 보고, 되도록 템플릿에 얹어서
보세요.

해상도는 갈래마다 목표가 다릅니다(`TARGET_LONG_EDGE`). A4 를 300dpi 로 찍으려면
긴 변이 3508px 이어야 하고, 모자라면 스크립트가 두 배까지 키웁니다. 현수막과
배너는 실물이 미터 단위라 원본으로 전면을 채울 수 없으므로, 템플릿이 그림을
«전면» 이 아니라 «띠» 로 쓰도록 짜 두었습니다.

## 확인하는 두 가지 방법

**`npm run print:check`** — 빌드가 떨궈 놓은 `out/print-templates.json` 을 읽어
값을 셉니다. 좌표·글꼴·색·해상도. 빠르고, CI 에 걸 수 있습니다.

```bash
GITHUB_PAGES=true npx next build   # out/print-templates.json 을 만듭니다
npm run print:check
```

**`/print/check/`** — 브라우저에서 마흔여덟 장을 실제로 엽니다. 사람이 편집기에서
하는 순서를 그대로 흉내 냅니다: 열기 → 글자 수정 → 사진 교체 → AI 문구 얹기 →
PDF 만들기. 만든 PDF 는 내려받지 않고 바로 뜯어서 면 수·크기·글자 수를 재고,
쓰인 글자의 폭이 글꼴 표에 빠짐없이 들어 있는지 봅니다. 한 장에 3~10초, 전부
돌리면 5분쯤 걸립니다.

둘 다 필요합니다. 앞의 것은 «값이 맞는가», 뒤의 것은 «열면 실제로 그려지는가»
를 답합니다. PDF 를 만들다 죽는 것도, 사진이 404 인 것도 앞의 것으로는
안 잡힙니다.

## 목록 화면

- `/print/` 갈래 여섯 개
- `/print/<갈래>/` 그 갈래의 여덟 장 + 업종·스타일·색 거르기
- `/print/t/<템플릿>/` 한 장을 크게 + 규격 + 배경 그림 프롬프트
- `/print/<갈래>/edit/?t=<템플릿>` 편집기

거르기 단추는 «그 목록에 실제로 있는 딱지» 만 세웁니다(`facetsOf`). 눌러도
결과가 없는 단추는 사용자에게 고장으로 읽힙니다.

## 값

인쇄물은 링크가 아니라 **파일** 을 파는 상품이라 다른 둘과 규칙이 다릅니다.

- 결제 전에도 편집·내보내기가 전부 됩니다. 대신 결과물에 «Cardly 미리보기»
  표시가 옅게 깔립니다(`lib/print/watermark.ts`).
- 결제하면 그 표시가 사라지고, **기한이 없습니다**. 보관 비용이 거의 들지
  않기 때문입니다.
- 값은 `lib/plan.ts` 의 `PRICES.print`, 데이터베이스의 `order_price('print')`
  두 곳에 있고 **데이터베이스 쪽이 진짜** 입니다.
