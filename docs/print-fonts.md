# 인쇄물 편집기 글꼴 — 출처와 라이선스

인쇄물 편집기(`/print`)에서 고를 수 있는 글꼴 여섯 벌입니다. **여섯 벌 모두
SIL 오픈 폰트 라이선스(OFL 1.1)** 이고, 상업적 사용·수정·재배포가 무료입니다.
인쇄물은 만든 사람이 팔 물건에 쓰는 경우가 많아, 라이선스가 애매한 글꼴은
아예 목록에 넣지 않았습니다.

| 편집기 이름 | 원 이름 | 굵기 | 배포처 | 라이선스 |
| --- | --- | --- | --- | --- |
| 프리텐다드 | Pretendard | 400·600·700 | github.com/orioncactus/pretendard | OFL 1.1 |
| 나눔고딕 | Nanum Gothic | 400·700·800 | Google Fonts (네이버) | OFL 1.1 |
| 고딕 A1 | Gothic A1 | 400·600·800 | Google Fonts | OFL 1.1 |
| 고운돋움 | Gowun Dodum | 400 | Google Fonts (yangheeryu) | OFL 1.1 |
| 본명조 | Noto Serif KR | 400·600·700 | Google Fonts (Adobe·Google) | OFL 1.1 |
| 도현 | Do Hyeon | 400 | Google Fonts (우아한형제들) | OFL 1.1 |

OFL 이 요구하는 것은 두 가지뿐입니다. 글꼴 파일 자체를 팔지 말 것, 그리고
파일을 재배포할 때 라이선스 사본을 함께 둘 것. 글꼴로 만든 **결과물**(인쇄물,
PDF, 이미지)에는 아무 제약이 없고, 결과물을 파는 것도 허용됩니다. 글꼴을 PDF
안에 심는 것(embedding)도 OFL 이 명시적으로 허용합니다. 그래서 PDF 에 심는
나눔고딕 파일 옆에 `public/print-fonts/OFL.txt` 로 라이선스 전문을 함께
두었습니다.

파일은 `app/fonts.ts` 가 `next/font/google` 로 내려받아 자체 호스팅합니다.
프리텐다드만 npm 패키지(`pretendard`)로 들어 있습니다.

## PDF 에 심는 글꼴

PDF 로 내보낼 때 파일 안에 실제로 심는 자형은 **나눔고딕 한 벌**입니다
(`public/print-fonts/NanumGothic-Regular.ttf`, `NanumGothic-Bold.ttf`,
라이선스 전문은 같은 폴더의 `OFL.txt`). 나머지 다섯 벌은 브라우저가
웹폰트로만 들고 있어 원본 파일을 꺼낼 수 없기 때문입니다.

그래서 다른 글꼴을 쓴 문서를 PDF 로 내보내면 자형이 나눔고딕으로 바뀝니다.
**이 사실은 내보내기 화면에서 사용자에게 그대로 알립니다.** 조용히 바꿔 두면
인쇄소에서야 발견하게 되고, 그때는 이미 늦습니다. 자형을 그대로 지키고 싶은
사용자에게는 PNG·JPG 내보내기(화면과 100% 같은 그림)를 안내합니다.

### 왜 프리텐다드가 아닌가

사이트의 기본 글꼴은 프리텐다드이고, npm 패키지로 파일도 들고 있으니 그것을
심는 것이 자연스러워 보입니다. 두 번 시도했고 두 번 다 실패했습니다.

1. **OTF 는 읽지 못합니다.** 프리텐다드의 `.otf` 는 CID 방식 CFF 로 만들어져
   있는데, PDF 를 만들 때 쓰는 `@pdf-lib/fontkit` 이 그 안의 FontMatrix
   연산자를 몰라 표 해독을 포기합니다(`Unknown operator 3079`). 글꼴을 심지
   못하니 내보내기가 통째로 실패합니다.
2. **TTF 판은 읽지만 쌍점이 어긋납니다.** 패키지의 `static/alternative` 폴더에
   TrueType 판이 있어 그쪽은 통과합니다. 그런데 fontkit 이 문장 안의 `:` 와
   `–` 를 다른 글자(대체 자형)로 바꿔 놓고, pdf-lib 은 글자 폭 표(W)를
   «유니코드로 직접 닿는 글자» 만으로 만듭니다. 그래서 바뀐 글자의 폭이 표에
   빠지고, 뷰어는 기본값 1em 을 씁니다. 화면의 `일요일 14:00–17:00` 이
   PDF 에서 `일요일 14:  00–  17:  00` 이 됩니다.

나눔고딕은 그런 대체가 없어 쓰인 글자의 폭이 모두 표에 들어갑니다. 덤으로,
편집기에서 나눔고딕을 고른 문서는 PDF 에서도 진짜 나눔고딕으로 나옵니다.

**새 글꼴로 바꾸기 전에 반드시 확인하세요.** 실제로 PDF 를 뽑아, 본문에 쓰인
글자의 글리프 번호가 모두 W 배열에 들어 있는지 봅니다. 빠진 번호가 하나라도
있으면 그 글자는 인쇄물에서 한 칸씩 벌어집니다.

### 왜 통째로 심는가

쓴 글자만 잘라 심으면(subset) 파일이 1MB 대에서 10KB 대로 줄어듭니다. 해
보았고, 실패했습니다. 같은 fontkit 의 자르개가 짧은 loca 형식에서 글자 자료를
짝수 경계에 맞춰 채우지 않아, 홀수 길이 글자 하나를 지나면 그 뒤의 글자들이
어긋난 자리를 가리킵니다. 화면의 «토요일 목공 교실» 이 PDF 에서 «요일 목공 교»
가 됩니다. 프리텐다드와 나눔고딕 양쪽에서 같은 증상을 확인했습니다.

글자가 몇 개 사라진 인쇄물을 인쇄소에서 발견하는 것보다 파일이 무거운 편이
낫다고 보았습니다. 대신 **실제로 쓰는 굵기만** 심습니다 — 굵은 글자가 없는
문서에는 한 벌만 들어가고, PDF 는 1MB 안팎이 됩니다.

### 다섯 벌을 모두 심으려면

각 글꼴의 정식 배포처에서 TTF 를 받아 `public/print-fonts/` 에 넣고,
`lib/print/fonts.ts` 의 `PDF_EMBEDDED_FONT` 를 글꼴별 표로 바꾸면 됩니다.
한글 글꼴은 한 벌에 2~4MB 라 여섯 벌을 모두 두면 20MB 가 넘고, PDF 를 만들 때
필요한 글꼴만 내려받는 구조가 함께 필요합니다. 2차 작업으로 남겨 두었습니다.
