# 다온 (DAON) — 모바일 청첩장 플랫폼

템플릿을 고르고 편집기에서 직접 내용을 채워 모바일 청첩장을 만드는 웹 서비스입니다.
**모든 기능이 무료이며 결제 절차가 없습니다.**

## 화면

| 경로 | 설명 |
| --- | --- |
| `/` | 홈 — 히어로, 템플릿 갤러리, 편집기 소개 |
| `/templates` | 템플릿 12종 전체, 카테고리 필터 |
| `/editor/[templateId]` | 편집기 — 좌측 21개 섹션 / 실시간 폰 미리보기 |
| `/preview/[templateId]` | 완성본 청첩장 전체 화면 |

## 편집기

좌측 아이콘 레일에서 섹션을 고르면 가운데 폼이 바뀌고, 오른쪽 폰 미리보기에 즉시 반영됩니다.

꾸미기 · 디자인 · 배경음악 · 오프닝 · 신랑 정보 · 신부 정보 · 미니앨범 · 예식 정보 ·
초대 글 · 계좌 정보 · 갤러리 · 안내사항 · 하객스냅 · 커플프로필 · 타임라인 · 비디오 ·
방명록 · 선물하기 · 참석여부 · 이미지 · 순서 변경

섹션을 켜면 청첩장에 추가되고 **순서 변경** 목록에 나타납니다. 순서는 드래그로 바꿀 수 있고,
각 패널에서 해당 섹션이 청첩장의 몇 번째에 놓이는지 확인할 수 있습니다.

## 디자인 토큰

색상·타이포·간격은 전부 `app/globals.css` 의 `@theme` 한 곳에서 정의합니다.
아이보리 베이스(`#FDFBF7`)에 더스티 로즈 포인트 1색(`#B08D80`, 텍스트·버튼용 `#8A6558` 은 WCAG AA 통과),
제목은 Noto Serif KR, 본문은 Noto Sans KR 입니다.

- `app/globals.css` — 디자인 토큰과 공통 컴포넌트 클래스
- `app/invitation.css` — 청첩장 렌더러 전용 스타일 (`--iv-*` 테마 변수)
- `app/motion.css` — 바텀 시트, 오프닝 애니메이션, 스크롤 리빌

## 개발

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # 프로덕션 빌드
npx tsc --noEmit # 타입 검사
npx eslint app components lib
```

## 배포 (GitHub Pages)

`main` 브랜치에 push 하면 `.github/workflows/deploy.yml` 이 정적 사이트를 빌드해 Pages 에 올립니다.
저장소 이름이 곧 basePath 가 되므로(`https://<user>.github.io/<repo>/`) 별도 설정은 필요 없습니다.

저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 지정해 주세요.

로컬에서 배포본을 그대로 확인하려면:

```powershell
$env:GITHUB_PAGES="true"; $env:NEXT_PUBLIC_BASE_PATH="/wedding-web"; npm run build
npx serve out
```

## 아직 서버가 필요한 기능

정적 사이트라 아래는 화면만 동작하고 데이터가 보관되지 않습니다.

- 참석 의사(RSVP) · 방명록 제출 — 브라우저 안에서만 반영
- 청첩장 발행 및 링크 생성
- 업로드한 사진 — `blob:` URL 이라 새로고침하면 사라짐 (임시저장은 텍스트만 보관)
- 지도 — 네이버·카카오 지도 SDK 와 API 키 필요
- 하객스냅 구글 드라이브 연동

## 모바일 초대장

링크를 받은 사람 앞에 **닫힌 카드**가 놓입니다. 앞장을 누르면 그 장이 왼쪽으로 넘어가며
열리고, 그 아래에서 초대장이 드러납니다 — 열기 전에는 스크롤이 잠깁니다. 초대장은
받아서 «여는» 물건이라, 링크를 누르자마자 글이 좌르륵 나오면 그건 청첩장 웹페이지이지
초대장이 아닙니다.

목록에서도 같은 카드가 같은 방식으로 열립니다. 마우스를 얹으면 그 자리에서 반쯤
펼쳐져 속면이 보입니다(`.oc-fold:hover`). 여는 일은 전부 CSS 가 하므로 목록은
서버 컴포넌트 그대로이고, 스무 장의 조판이 자바스크립트로 실려 나가지 않습니다.

청첩장(`/templates`, `lib/invitation`)과는 별개의 물건입니다. 청첩장은 길게 내려 읽는
페이지이고, 초대장은 한 장짜리 카드입니다. 코드도 서로 닿지 않습니다.

| 경로 | 설명 |
| --- | --- |
| `/invitation-card` | 디자인 목록 — 스무 벌. 갈래 칩으로 거르고, 카드는 호버로 열립니다 |
| `/invitation-card/[design]` | 디자인 한 벌. 실제로 열리는 카드를 그대로 놓습니다 |
| `/invitation-card/make` | 만들고 보내는 화면. `?d=<디자인>` 또는 `?c=<초대장>` 으로 시작 |
| `/invitation-card/v/[design]` | **받는 사람이 여는 화면.** `?c=<초대장>` |

### 보내는 방식 — 서버가 없습니다

정적 사이트라 저장할 곳이 없습니다. 그래서 초대장 내용을 서버에 두고 번호를 받아 오는
대신, **내용 자체를 주소 뒤에 실어** 보냅니다.

```
/invitation-card/v/poppy/?c=eyJkIjoicG9wcHkiLCJ0Ijoi7Ju...
```

- 가입도 결제도 필요 없고, 적은 글이 브라우저 밖으로 나가는 때는 링크를 직접 보낼 때뿐입니다.
- 링크가 살아 있는 한 초대장도 살아 있습니다. 만료도 삭제도 없습니다.
- 대신 주소가 깁니다. 그래서 열쇠말을 한 글자로 줄이고(`title` → `t`) 빈 칸은 싣지 않습니다.
  **한 번 정한 열쇠말은 바꾸지 마세요** — 이미 보낸 링크가 전부 안 열리게 됩니다.

보내기는 `navigator.share`(카카오톡·메시지), `sms:`, 링크 복사 세 가지입니다.

### 표지 그림 — 만들어서 들입니다

표지는 그림입니다. 그 위에 제목도 날짜도 얹지 않습니다 — 얹으면 글자가 묻히지 않게 깐
베일이 그림을 흐리고, 고쳐 쓰라고 넣어 둔 예시 문구가 그림 위에 인쇄되어 카드가 광고
배너처럼 읽힙니다. 실물 인사장이 그렇듯 앞은 그림이고 말은 안에 있습니다. 제목은 카드를
열면 나오는 속 왼쪽 면의 머리가 됩니다.

스무 장 모두 Google Gemini 이미지 생성으로 만들었습니다. 손으로 짠 벡터 도형은 아무리
다듬어도 클립아트로 읽히고, 색면과 괘선만으로는 실물 카드가 주는 화사함이 나오지
않습니다.

```
export GEMINI_API_KEY=…          # PowerShell: $env:GEMINI_API_KEY = '…'
node generate.mjs                # → cardly-artworks/*.png (3:4 · 4K) + preview.html
ONLY=02,07 node generate.mjs     # 몇 장만 다시 뽑을 때
npm run art:import               # → public/art/*.webp + lib/occasion/palette.json
npm run og:make                  # → public/og/invitation-card/*.jpg
```

- **4K 로 받습니다.** 표지는 카드 화면을 가득 채우는 그림이라 배율 2배·3배 기기에서
  흐려지면 그것으로 끝입니다. 줄이는 것은 언제든 되지만 없는 화소는 못 만듭니다.
- 모델 이름은 코드에 박지 않고 실행할 때 API 에 물어 **화질 순으로 늘어놓습니다**
  (`gemini-3-pro-image` → `3.1-flash-image` → `2.5-flash-image`). 화질 좋은 모델은 하루
  몫이 적어 스무 장을 다 만들기 전에 막히는데, 막히면 그 모델을 이번 판에서 빼고 다음
  것으로 마저 만듭니다. 막힌 모델은 429 가 아니라 «응답을 시작하지 않는» 식으로 막히므로
  호출마다 시간 제한을 겁니다.
- `cardly-artworks/` 원본은 4K 라 장당 10MB 가 넘습니다. 커밋하지 않습니다(`.gitignore`).
  배포에 나가는 것은 `import-artwork.mjs` 가 5:7 로 잘라 만든 webp 뿐입니다.
- **액자 벗기기** — 이따금 그림 대신 «인쇄된 카드를 찍은 사진»(손에 들린 카드, 흰 여백과
  그림자)이 옵니다. 프롬프트로 대부분 막았고, 그래도 남는 것은 들일 때 테두리를 잘라
  냅니다(`isFramed`).
- 카드의 색 세 개(종이색·글자색·강조색)는 손으로 고르지 않고 그림에서 뽑아
  `lib/occasion/palette.json` 에 적힙니다. 뽑은 뒤 본문 4.5:1 · 강조 3:1 을 넘길 때까지
  명도를 옮깁니다. 그림을 다시 만들면 색도 저절로 따라옵니다.

### 구조

```
lib/occasion/
  types.ts      자료 구조 — Design 이 «디자인 한 벌», InviteData 가 «채워 넣은 내용»
  designs.ts    디자인 스무 벌 — 그림 + 판짜기 + 밝기. 색은 palette.json 에서
  palette.json  그림에서 뽑은 색 (스크립트가 씁니다 — 손으로 고치지 마세요)
  occasions.ts  행사 일곱 갈래와 갈래별 예시 내용
  format.ts     날짜·시간·지도·전화·문자 링크
  share.ts      초대장 ↔ 주소 문자열
components/occasion/
  faces.tsx       넉 면의 조판 — 표지 · 인사말 · 일정 · 뒤표지
  fold.tsx        목록에 서 있는 카드. 호버로 열립니다
  folded-card.tsx 3D 로 열리는 큰 카드 — 상태는 «몇 번째 면인가» 하나뿐
  gallery.tsx     갈래 칩. 카드는 children 으로 받아 서버 HTML 그대로 둡니다
  maker.tsx       만들고 보내는 화면
  viewer.tsx      받는 사람 화면
app/occasion.css  전용 스타일. 색은 전부 --oc-* 변수
generate.mjs               표지 그림을 만드는 스크립트
scripts/import-artwork.mjs 그림을 제품에 들이고 색을 뽑는 스크립트
```

### 설계 원칙

- **미리보기와 실물이 같습니다** — 목록의 작은 카드도 큰 카드와 같은 컴포넌트를 zoom 으로
  줄여 그립니다. 따로 «작은 판» 을 만들면 반드시 어느 한쪽이 틀어집니다.
- **덮개는 왼쪽으로** — 접힌 자리가 왼쪽이고, 자유단인 오른쪽을 들어 왼쪽으로 넘깁니다.
  반대로 만들면 오른쪽에서 왼쪽으로 읽는 책이 됩니다.
- **각도는 변수에 담습니다** — 상태가 하는 일은 `--fc-p1…4` 를 바꾸는 것뿐이고 도는 일은
  한 곳에서만 합니다. 그래서 목록의 호버 같은 새 상태를 규칙 하나로 더할 수 있습니다.
- **색은 그림에서 뽑습니다** — 지어낸 색을 그림 위에 얹으면 아무리 예쁜 색이어도 조잡해집니다.
- **모바일 우선** — 카드는 5:7 비율을 지키면서 화면 높이 안에 들어오도록 «너비»를 줄입니다.
  높이를 잘라 맞추면 비율이 찌그러집니다.
- **누르는 것은 44px 이상**, 본문과 버튼 색은 배경 대비 4.5:1 이상.
- **과하지 않은 움직임** — 여는 연출과 등장(투명도 + 14px 상승)뿐이고,
  `prefers-reduced-motion` 이 켜져 있으면 열린 상태로 시작합니다.
- **의존성 없음** — 3D·등장·공유 모두 브라우저 기본 기능으로 구현했습니다.

## 이미지 라이선스

- `public/samples/` — Pexels 라이선스 (상업적 이용·수정 가능, 출처 표기 불필요)
- `public/art/` — Google Gemini 이미지 생성으로 만든 초대장 표지 스무 점. 생성물의 권리는
  API 키 소유자에게 있으므로 상업적 이용에 제약이 없습니다. 사람·상표·실존 인물을 담지
  않도록 프롬프트에서 막았습니다.
